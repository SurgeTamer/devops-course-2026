# Конфигурация виртуальной машины devops-vm

## 1. Параметры машины
- Объём оперативной памяти: 2 ГБ.
- Количество ядер процессора: 2.
- Объём дискового накопителя: 25 ГБ.
- Тип и версия гостевой ОС: Linux, Ubuntu Server 25.04 LTS 64-bit.

## 2. Сетевые интерфейсы
В виртуальной машине два сетевых адаптера:
- `NAT`. Полученный адрес: `10.0.2.15`. Обеспечивает доступа виртуальной машины в интернет.
- `Виртуальный адаптер хоста (Host-only)`. Полученный адрес: `192.168.56.101`. Обеспечивает прямой доступ с хостовой системы к веб-серверу.

## 3. Правило проброса портов
Правило настроено для NAT для обеспечения SSH-доступа с хостовой системы:
- Порт хостовой системы: `2222`
- Порт гостевой системы: `2222` (изменен с 22 в процессе усиления защиты SSH)

## 4. Учётные записи
- student: Создана при установке ОС. Входит в группы `student`, `sudo`, `adm`, `cdrom`, `dip`, `plugdev`, `lxd`. Способ аутентификации: пароль (используется для локального входа).
- devops: Создана вручную (`adduser`). Входит в группы `devops`, `sudo`, `users`. Способ аутентификации: по SSH-ключу (приватный ключ `devops_vm` хранится на хосте, публичный — в `~/.ssh/authorized_keys`). Парольная аутентификация для SSH отключена.
- root: Прямой вход по SSH запрещён.

## 5. Служба SSH
- Текущий порт: `2222`.
- Используется дополнительный файл `/etc/ssh/sshd_config.d/99-hardening.conf`. Основной файл `/etc/ssh/sshd_config` не изменяося.
- Изменённые директивы в `99-hardening.conf`:
    - `Port 2222` (изменение стандартного порта)
    - `PermitRootLogin no` (запрет входа под root)
    - `PasswordAuthentication no` (запрет входа по паролю)
    - `PubkeyAuthentication yes` (разрешён вход только по ключам)
    - `PermitEmptyPasswords no`
    - `MaxAuthTries 3`
    - `LoginGraceTime 30`
    - `AllowUsers devops` (разрешён вход только пользователю devops)
    - `X11Forwarding no`
    - `ClientAliveInterval 300`
    - `ClientAliveCountMax 2`

## 6. Правила межсетевого экрана (UFW)
- Статус: active.
- Политика по умолчанию (входящие): deny (запрещено всё, что не разрешено).
- Политика по умолчанию (исходящие): allow.
- Включено логирование: medium.
- Перечень разрешающих правил:
    1.  `2222/tcp` (LIMIT) — SSH с ограничением частоты подключений (защита от брутфорса).
    2.  `80/tcp` (ALLOW) — HTTP (для веб-сервера Nginx).
    3.  `443/tcp` (ALLOW) — HTTPS (для веб-сервера Nginx).

## 7. Снимки состояния
В VirtualBox созданы следующие снимки:
1.  01-clean-install: Создан сразу после установки ОС и выполнения `apt update && apt upgrade`.
2.  02-keys-configured: Создан после настройки пользователя devops, создания SSH-ключей на хосте и успешного входа по ним.
3.  03-ssh-hardened: Создан после изменения конфигурации SSH (порт 2222, запрет root и паролей) и настройки правил UFW.

## 8. Веб-сервер

- Устанавливаемый пакет: `nginx` (стандартный репозиторий Ubuntu).
- Путь к конфигурации ресурса: `/etc/nginx/sites-available/devops-site` (активирован символической ссылкой в `/etc/nginx/sites-enabled/`). Стандартный конфиг `default` удален.
- Каталог ресурса: `/var/www/devops-site`. Владелец: `devops:devops`. Права: `755` для каталогов и `644` для файлов (модель «владелец пишет, веб-сервер читает»).
- Путь к сертификату: `/etc/ssl/certs/devops.crt` (права `644`, владелец `root`).
- Путь к закрытому ключу: `/etc/ssl/private/devops.key` (права `600`, владелец `root`).
- Команда формирования сертификата:
    ```bash
    sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
      -keyout /etc/ssl/private/devops.key \
      -out /etc/ssl/certs/devops.crt \
      -subj "/CN=devops.local" \
      -addext "subjectAltName=DNS:devops.local"

## 9. Контейнеризация
- Способ установки Docker Engine: Официальный репозиторий Docker (docker-ce).
- Версия Docker Engine: v27.x (или ваша актуальная версия).
- Участники группы docker: devops.
- Расположение проекта на сервере: `/home/devops/app`.
- Расположение файла .env: `/home/devops/app/.env`, права 600, владелец devops.
- Публикуемые порты и адреса: Порт 5000 опубликован строго на `127.0.0.1:5000`. Порт СУБД 5432 не публикуется.
- Именованные тома: `app_db_data` (данные PostgreSQL).
- Конфигурация обратного прокси-сервера: Локация `/app/` в Nginx проксирует запросы на `http://127.0.0.1:5000/` с передачей заголовков Host, X-Real-IP, X-Forwarded-For, X-Forwarded-Proto.
